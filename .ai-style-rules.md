## Golden Files

- `src/app/(protected)/dashboard/page.tsx` — Server Component que obtiene contexto autorizado, redirige si falta y delega la interacción visual.

## Naming & State-Control Rules

- Usar kebab-case para archivos y PascalCase para componentes.
- Mantener las rutas como Server Components salvo que requieran estado o eventos del navegador.
- Encapsular estado interactivo en el componente cliente más pequeño posible.
- Colocar tipos y datos constantes antes del componente principal, y helpers antes del export.
- Separar imports de framework, imports internos y lógica mediante líneas en blanco.
- Validar entradas no confiables con Zod y verificar sesión y alcance dentro de cada Server Action.
- Limitar consultas y mutaciones clínicas por unidad; seleccionar consultorio no amplía permisos.
- Usar fixtures explícitos con los mismos DTO que consumirá la integración real.
- Mantener textos de interfaz en español y marcar los datos de demostración.

## DONTs

- No convertir una página completa en Client Component por una interacción local.
- No mover autorización al cliente ni confiar solo en el layout para proteger una Server Action.
- No introducir datos clínicos reales, secretos o umbrales universales en fixtures o componentes.
- No duplicar DTO entre UI, acciones y consultas.
- No agregar dependencias de UI cuando un recurso local pequeño y accesible resuelve el caso.
- No mezclar cambios de backend o esquema con una iteración puramente visual.
